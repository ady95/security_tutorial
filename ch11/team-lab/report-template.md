# Purple Team 결과 보고서 작성 양식

이 문서는 작성 양식이며 실측 결과가 아닙니다. 실제 코드·정책·입력·모델 판과 hash를 채우세요. 접속 정보와 실제 비밀값을 공개 저장소에 붙이지 않습니다.

| 항목 | 기록 |
|---|---|
| 대상·담당자·일시 | 자신의 로컬 랩과 검토 주체 |
| 정상 목표 | 허용해야 할 업무 |
| 사례·전제·입력 hash | 변경 가능한 곳과 접근 권한 |
| 코드·정책·문서 hash | 전후 비교의 기준 |
| 대화·임베딩 모델 판 | 실제 사용한 경로 |
| 엔진 | replay 또는 live; 합산하지 않음 |
| 완료·미판정·반복 수 | 분모와 제외 이유 |
| weak의 시도·효과 | 감사 행과 파일 효과 |
| guard의 시도·대기·효과 | 판단과 실제 실행을 구분 |
| 정상 대조군 | N1 주문 조회 또는 합의한 업무 |
| 탐지·오탐·누락 | 정답표와 검토 근거 |
| 남은 위험·담당자·다음 시험 | 읽기 권한, 원본 목록, 로그·승인 보관 등 |

모델이 따르지 않은 입력과 가드가 차단한 호출을 구분합니다. approved-docs.json의 내용이 옳다는 판단과 변경 승인도 기록합니다. 가짜 인증 표식이 감사·승인에 남은 경우 반출만 막혔다고 기록하며 전체 노출 해결로 쓰지 않습니다.
